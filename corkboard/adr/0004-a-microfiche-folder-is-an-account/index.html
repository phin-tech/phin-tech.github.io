A Microfiche folder is an Account, reached through Microfiche's API

Corkboard shows the Tasks in a Microfiche folder as Issues, following 0002: the folder is an Account, its prefix is the Account's one Team, a Task is an Issue named by the prefix and the Task's random id: (HOME-k3f9), its child Tasks are Sub-issues and a depends: is a blocked-by Link. A top-level folder inside it is a Project, and every Note beneath that folder, however deep, is one of its Milestones, named by its path; Notes outside any folder hold Issues in no Project, as the Inbox does. Corkboard reaches the folder only through Microfiche's API, as it reaches Linear only through Linear's, and keeps a Local copy of it the same way. Both apps are ours, so what doesn't fit is added to Microfiche rather than made optional here: an Issue still always has a Team and an identifier.

The model's words stay Linear's, but each screen shows one Source and uses its words, so a Microfiche Issue shows as a Task and its Milestone as a Note. Lists and Searches span the Accounts of one Source and never two, because a list of Issues beside Tasks would need words for neither.

Open questions #

  • Microfiche's Linear Extension syncs Linear Issues into linear.fiche and linear/, so a folder holds copies of Issues Corkboard already shows under Linear. Leaving out the Notes an Extension owns (its manifest's notes) would drop the copies but keep a hand-written Task carrying linear:HOME-31, which is a step of yours, not a copy. Left until the read-only slice shows whether the copies get in the way.

Considered Options #

  • Team made optional in Corkboard. Every Filter, identifier and Nesting would have to handle an Issue with none, which is the neutral model 0002 turned down.
  • Numbered identifiers (HOME-14), as Linear's are. Linear's server is the one place an Issue is made, but a folder is written by hand, by agents and on several Macs, so a counter could give two Tasks one number. If identifiers turn out hard to say, an alias Field can name a Task as well.
  • Linking Microfiche's crates. No process to run, but the two workspaces would have to agree on their shared dependencies' versions and be released together.
  • Running microfiche for each Change. Independent, but every Change waits for a process to start, and nothing says when a Note is edited by hand.
