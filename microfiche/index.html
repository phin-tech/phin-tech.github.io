Microfiche

A modal, GUI-first outliner for notes with tasks mixed into them, written as plain-text .fiche files. It's for macOS, and moves like Vim.

Everything here comes from the notebook of Pepper, a dog with a lot going on. His Notes are in samples/pepper if you'd like to open them yourself. The box in the corner of each GIF shows the keys being pressed.

Move things around #

Press m to pick up an Item or a selection, step the line to where it should go, and press enter. Sausage belongs at the top.

SPC i r sends an Item to another Note or Heading, and saves both.

Get around a Note #

[[ and ]] go between Headings, and ctrl-cmd-up and ctrl-cmd-down do the same while you're typing.

SPC t h indents each section by its Heading's level. It's only how the Note looks, and the file doesn't change.

The Launcher finds Commands, Notes, Headings and Tasks across the folder.

Tasks #

enter moves a Task through its states.

The Capture box answers a global hotkey, so a thought can reach your Inbox from anywhere.

Read it back #

SPC t r shows the Note rendered, and a Task's state can still change there.

Find a key #

SPC shows what each next key does, and SPC ? lists the common ones. The key guide has the rest.

Install #

You'll need Rust and just.

just install

That puts the app in /Applications, adds microfiche to ~/.cargo/bin, and starts the Capture agent.

From a terminal #

microfiche help lists every subcommand. They work on the folder in your config, or the one named by --folder, and --json prints JSON.

microfiche agenda
microfiche query todos +work due:\<fri
microfiche task work.fiche:12 done
microfiche task work.fiche:12 --due "fri 3pm" --tag urgent
microfiche add work.fiche --under Plans "Book the venue due:in two weeks"
microfiche refile work.fiche:12 archive.fiche --under Done
echo "- [todo] Call the vet" | microfiche append pepper.fiche --under Errands
microfiche rename plans/q4.fiche archive/2025-q4.fiche
microfiche meeting "Plan Q4" --on 2026-11-09T15:00

A subcommand's name takes priority over a folder with that name, so write microfiche ./list to open one.

With an agent #

SPC f m shows the setup for Claude Code, Claude Desktop, Codex, Cursor, VS Code and raw JSON, ready to copy.

microfiche mcp serves the same abilities to an agent over stdio: it can list, read, query and search Notes, find what links to a Note, Heading or Task, make an Event's Meeting Note from the meeting Template, see the Agenda, Capture, add Tasks anywhere, change a Task's state, dates, Fields, tags or title, refile a Task or Heading, create, edit, insert into or rename Notes, and try Scripts on real or sample Tasks without saving what they make, then save the ones that work. For Claude Code:

claude mcp add microfiche -- microfiche mcp --folder ~/notes

For work across many Notes, an agent can use Code mode: it writes JavaScript that calls those same abilities as functions, so it needn't make hundreds of calls one at a time. run_code can only read, so you can approve it freely, and run_code_with_writes can change Notes. The code runs with no files, network or imports of its own, for at most 5 seconds. If it fails partway, finished writes stay and the agent is told which they were.

It only reaches .fiche files inside that folder, and the Scripts in its .microfiche/scripts. A Script is tried on sample Tasks before it's saved, and one that's already there stays unless the agent asks to replace it. If the app has a Note open, the Note picks up a change by itself, or keeps its unsaved edits and says so. Renaming, retagging or refiling a Task rewrites the Links that reach it, in any Note in the folder. So does renaming or moving a Note, and its own Links change to match its new folder, though its Images don't.

The Agent sidebar's agent can also show you a Note, at a Heading or a line, what a Query or Tag finds, or the Agenda, when you ask to be taken there. It moves the window the sidebar is in, and stays put if the Note on screen has unsaved changes. That agent also reads and writes the Note on screen through the editor: it sees your unsaved edits, and what it writes arrives as an edit you can undo with u, left for you to save. It can also ask where you are, with here, which gives your cursor's line, the Heading it's under and what you've selected, and write there with write_at_cursor, in place of the selection or as lines below the cursor. Queries, searches and the Agenda see the Note on screen as the editor has it. It can suggest a change instead of making it, which opens as a diff to take with enter or drop with escape, and list the calendar's Events, which only the app can read. An agent you run yourself isn't offered these, and writes to files, because it has no window.

Extensions #

An Extension is a Script that can ask for more. It lives in .microfiche/extensions/<name>/ as an extension.toml, which says what it wants, and a main.js, which exports generate(host, input) and returns text. It can fetch from the hosts it names, and only once you've allowed exactly that:

microfiche extension key linear      # save a key in the keychain, from a prompt
microfiche extension grant linear    # see what it asks for, and allow it
microfiche extension run linear

The key never reaches the JavaScript: Microfiche adds it to the request. What you've allowed is kept in ~/.config/microfiche/grants.toml, outside your Notes, and an Extension that changes what it asks for is asked about again. extension disable <name> and enable <name> switch one off and on, and revoke <name> takes back what you allowed so it asks again. The app's Extensions page (Microfiche menu, or the Launcher) has a switch for each. In the app, SPC x lists Extensions with Scripts, and shows one that isn't allowed yet as a row saying what it asks; :name runs one. An agent's Code mode can't run them. samples/pepper has a linear Extension: :linear lists your open Linear issues as Tasks, and :linear sync keeps linear.fiche (a Task for each issue) and a Note for each issue in linear/ up to date, without ever deleting anything. It rewrites only what is under ## From Linear in each issue's Note, so what you write under ## Notes stays. An extension that writes Notes names the places in extension.toml as notes = ["linear"], and you allow that the same way. The Linear query is written like Microfiche's own, in linear.toml: query = "@me todos project:Website,Billing +bug -priority:low". @name is a person, +word a label, - or NOT leaves a word out, and filter takes Linear's own IssueFilter for anything else. Several named syncs can each fill their own linear/<name>.fiche and folder. Your settings for an extension go in .microfiche/extensions/<name>.toml beside its folder (linear.toml), so updating the extension never touches them, and changing them needs no new grant.
