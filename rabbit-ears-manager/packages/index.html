The station's packages

Agreed 2026-10-29; steps 1 to 4 built the same day.

Sources/Shared held everything the apps share: models, providers' clients, settings, views and players. Every app compiled all of it, and Antenna Tower (the server) compiled the Manager's views and VLCKit to get at the few parts it runs. The station is now split by layer into SwiftPM packages, so the server can build without the views and, later, on Linux (linux-server.md).

Where it's going #

Package (target) What's in it Runs on
RetroLineup (RetroLineup) lineup rules, IPTV parsing, and the games' data Apple, Linux
RetroLineup (RetroSports) the sport rules: reading event folders, sorting slots into sports and games, ESPN's schedules, Jev. Never in a screen's app (App Review: docs/sport-channels.md) Apple (Manager), Linux
RetroRelay the relay's client side, remote management's protocol (the relay itself is the Go tower) Apple, Linux (not RemoteControl)
Station (StationCore) what the station is, apart from how it looks: channels and their settings, profiles, the providers' clients (IPTV, Plex, Pluto, the MBTA, weather, news), the guide, search, On Demand's catalog and downloads Apple, Linux
Station (StationJobs) the Manager's own jobs: event schedules, sports settings and sorting, Jev's review, channel linking, guide files, On Demand's tagging (the Go tower runs the same for the station) Apple (Manager), Linux
StationUI what the screens and the Manager show: themes, the guide, the channels' views and players, StationModel. Everything public, for now (below) Apple

The app folders end up holding only @main, plists and assets.

Rules #

  • Nothing in StationCore draws. No SwiftUI, AVKit, VLCKit, MapKit or SceneKit. AppKit and UIKit appear only behind #if os(…), for lifecycle notifications.
  • A model doesn't live in its view's file. When a type is both what a thing is and how it looks, split it. A channel module is a ModuleDefinition (core) and a ChannelModule screen (UI); StationTheme is which look it is (core), with its colours in an extension (UI). See channel-modules.md.
  • No compile flags across packages. A package can't see an app's MANAGER or RELAY. Ask AppKind.current (set first thing in each main) instead.
  • Only what another module uses is public. Narrowed 2026-10-29 by building every app with nothing public and putting public back where the compiler asked: about 1,200 lines rather than 1,600. That includes public inits for structs the apps build, and Sendable said outright on public value types the apps send between tasks (only internal types get it inferred). Tests reach internals with @testable import.

Steps #

  1. Split mixed files (done, 4e6b294). Module definitions, the radio catalog, the weather store, the Video Store's titles, ad block's settings, the theme's kind, and a title's source each got a file of their own, and EventChannel stopped using MANAGER.

  2. StationCore (done). 65 files moved from Sources/Shared, and every app imports it. What stays in Shared imports a UI framework, or is a view model: StationModel, StationRemote, OnDemandBrowser, GuideCursor, WeatherStore.

  3. StationServer (done). RemoteServer, StationMirror, RelayHost, RelayHandover's tower side, OnDemandTagger and StorageCache from Sources/Manager: what TowerMain.serve() starts. The Manager and the tower link it. RemoteLink and Invite went to StationCore instead: every app joins a server with them. The seams:

    • RemoteServer reports and runs the event jobs through EventJobs, which the Manager's EventRefresher is; their keys are EventRefresh, in the core.
    • The Manager adds its assistant's switch to the server's settings (ServerSetting.hostSettings).
    • Restarting is the tower's alone (AppKind.current == .tower), and RemoteLink keeps the relay's status as JSON, which the Manager decodes.
    • Handing the station over to the tower stays in the Manager (RelayHandoverManager.swift): it starts the tower's launchd agent. Jobs (EventRefresher, EventScan, SportReview) and the assistant stay in the Manager: the tower is the broadcast, the Manager the control room.

  4. Linux (done). just linux-check builds and tests the three packages in Docker (Swift 6.3 with SQLite's headers). What stands in for Apple's frameworks on Linux:

    • Logger (RetroLineup's LinuxLogger.swift) writes os.Logger's calls to standard error, privacy: and all.
    • SQLite through a CSQLite system library (libsqlite3-dev).
    • StreamingFetch for URLSession.bytes: a live address's redirect and the start of epg.pw's guide, cancelled once read.
    • swift-crypto for CryptoKit (the mirror's sealing, R2's signing, SHA256).
    • Keychain keeps each secret as a 0600 JSON file under $STATION_SECRETS (default ~/.local/share/antenna-tower/secrets).
    • iCloud's key-value store is an empty stand-in (NoCloud.swift), and AppLifecycle.leaving is nil: there's no app to leave.
    • The relay advertises itself through avahi-publish when it's installed, and looks at its address each minute instead of watching the network path.

    Not on Linux yet:

    • Read-ahead (On Demand fetch's local server is an NWListener): titles play from their address. Moving it onto Hummingbird is next.
    • Posters stay JPEG, not HEIC.
    • The VPN guess (NetworkRoute) always says no tunnel.
    • Bonjour browsing (RelayFinder): the server never looks for a relay.
    • The phone remote's listener and client (RemoteControl).
    • Tests that need a listener: FetchTests (a local NWListener server), the TV's diagnostics server, and the remote's round trip.

    The server itself runs on Linux as antenna-tower-server (linux-server.md stage 3).

  5. UI packages. Group the views by which apps use them. Likely groups:

    • StationUI: themes, the guide, the channels' screens and menus (TV and phone);
    • Players: AVKit and VLC (TV and phone);
    • ManagerUI: the Manager's windows and panes.

Moving a target's files #

Step 2 made the core public with tools rather than by hand. Step 3 will do the same:

  1. Move the files with git mv, and add import <Target> to the files that use them.
  2. Add public to every declaration with no access level, except locals, protocol members and members of private types. A swift-syntax rewriter does this.
  3. Give every public struct without an initializer a public memberwise one, and every public class a public init() {}.
  4. Build. For each type named in a Sendable error, add Sendable. Repeat until clean. Check nested types named alike (Kind) by hand.

Step 5, built 2026-11-02: StationUI #

All of Sources/Shared (67 files, 18,600 lines) moved to Packages/StationUI as one package, StationUI, in one commit. The apps are now @main, plists and assets, and Sources/Manager.

  • ManagerUI (Packages/ManagerUI) took Sources/Manager the same way: its windows, panes and assistant. The Manager's app is ManagerMain.swift and the plist.
  • Players (Packages/Players) holds OnDemandEngine and its two engines (AVEngine, VLCEngine), VLCSurface and Subtitles: the only package that imports VLCKit. StationUI and ManagerUI depend on it. The live channels' views still use AVKit directly, in StationUI.
  • The tower links no UI. Its target is Sources/AntennaTower and StationCore, StationServer and the relay: no Sources/Manager, no StationUI, no VLCKit (otool -L shows none).
  • Everything is public. The tools were rebuilt as scripts/publicize.py (adds public to declarations with no access level, at the top level and in type bodies) and scripts/fix-access-errors.py (reads a build log: adds Sendable, public where a protocol asks, and a public init to a type named in "initializer is inaccessible"). Narrowing it to what the apps use is the same compiler loop in reverse, and is worth doing once the package is split: most views are only reached through a root view.
  • just check-tvos emits StationUI as a module, then type-checks the TV app's sources against it.
