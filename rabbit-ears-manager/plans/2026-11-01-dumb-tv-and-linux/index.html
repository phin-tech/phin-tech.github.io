Decisions already made #

  • The TV is dumb, for App Review. No sport rules, Jev or folder sorting in a screen's app. Anything sports goes in RetroSports or StationJobs, never Sources/Shared, TVApp, iOS, StationCore or the RetroLineup target.
  • Providers stay on the TV. Logins and Xtream code are fine: other IPTV apps (UHF) do that. Don't move them for review's sake.
  • Stale schedules: a screen plays the last sort however old. Past 90 minutes the coming-up card says how old; with none, it waits for the guide.
  • Tower = broadcast, control room = logic. The jobs and the assistant go in a second headless service, not the tower (ADR 0003 decision 7).
  • Swift, not Go. (Reversed 2026-11-02 for the tower: see ADR 0005, tower/.) The server shares its models, formats and parsing with the apps. Shrink the image with the Static Linux SDK if size matters.
  • Three kinds of channel: linear (one stream and its guide), app (the station draws it) and multi (one number, several things, a mini guide).
  • Commit straight to main. One design question at a time, lettered options with a recommendation.
  • Use the review notes honestly: a player for your own IPTV subscriptions and Plex, set up from a Mac. Guideline 2.3.1 rules out hidden features.

1. ChannelSchedule replaces eventGames #

The next job. The goal is that "games" is gone from the screens: on a TV a sport channel is just a multi channel with a schedule. Option (A) was agreed: sport and always-on channels only, shaped so groups can fold in later.

/// What a channel has on, as the control room worked it out.
public struct ChannelSchedule: Codable, Equatable, Sendable {
    var channel: IPTVChannel   // as scheduled for, like EventGames.channel
    public var asOf: Date
    public var items: [Item]   // in the channel's order: by entry, then start

    public struct Item: Codable, Equatable, Sendable {
        public var id: String      // stable: "game-<streamID>" or "stream-<id>", as OnAir.id
        public var title: String
        public var detail: String? // the source's own note on the row: "MLB 04"
        public var entry: Int      // index in channel.entries, for the order of onAir
        public var start: Date?    // nil: no time (an always-on stream, or a group's member)
        public var end: Date?      // "live until 5:00 PM"
        public var dated: Bool     // false: the day wasn't given
        public var plays: [Play]   // best first
    }
    public struct Play: Codable, Equatable, Sendable {
        public var source: Source
        public var broadcast: String  // "NFL PPV 4K", "Rangers Broadcast"; copies on other logins share it
        public var foreign: Bool      // commentary in another language
    }
    public enum Source: Codable, Equatable, Sendable {
        case channel(id: String)   // a group's member: unused for now
        case stream(id: String)    // one of the channel's own streams
        case feed(IPTVFeed)        // login, stream id and name: all `feeds(for:)` and `FeedChoice` read
    }
}

Checked against what the TV reads, the sketch needed these, now in it:

  • Stale schedules. A screen plays the last sort however old, and sorts are up to 30 minutes apart, so the control room never filters by "now". It publishes every showing as its own timed item, and the TV filters by time: onAir keeps its isLive check, and only the sport rules leave.
  • Broadcasts. Game.broadcasts and feeds(preferring:) (used by EventChannelView and StationMenu) are derived from folder names and quality tags, which is sport logic. The control room names each play's broadcast; the TV groups plays by that name in order, and puts the chosen group's plays first with the rest as backups.
  • Feeds. Source.feed carries an IPTVFeed, so iptv.feeds(for:) and FeedChoice.label need nothing from the sport's slots. The feed's note ("Spanish", "Away Feed") goes into broadcast, not a field of its own.
  • foreign is on Play, so the Feed page can tag it.
  • The entry. entryIndex(of:) reads slot.source, which the TV can't see any more, so Item.entry carries it and onAir just sorts by it.
  • A stable id. Item.id.
  • A stream's showing. The item's title, and end for "live until"; with no start or end the row says "always on". A stream with several showings gets one item each.
  • The row's note. Item.detail, for "MLB 04", which detail(_ game:…) reads from feeds[0].slot.event.slot.
  • Guide blocks. GuideStore lays Games.blocks out through EventSchedule, which is moving to RetroSports (step 4): write the block layout over ChannelSchedule items first, then move.

2. Stop sending sports data to screens #

sportSettings, eventSchedules, sportSchedule, sportJudged and sportGuides still reach TVs, which don't read them. This is tidying, not a review matter: review never sees synced data unless given a demo station. eventSchedules and sportGuides are the large ones.

  • The server can't tell a screen from a Manager: isManager(device) is about profiles, and a phone with a manager profile is still a screen. A device should say what it is: an app= query on GET settings, next to build, or a kind saved at pairing.
  • Add SettingsSync.stationOnlyKeys, and filter them in RemoteServer (GET settings, about line 279) as managerOnlyKeys is.
  • The R2 mirror has two snapshots (StationMirror.writeSettings): filter watch. A manager-profile phone reads full and would still get them. Either accept that or add a third snapshot. Accepting it is simpler.
  • iCloud: screens on the old route still get them through SettingsSync.keys. Make the list depend on AppKind, or leave it until iCloud goes.

3. Finish the reorganization: UI packages #

This is what started the work: Sources/Shared shouldn't be a grab bag. The models, clients, server and jobs have left it, but it still holds 67 files and about 18,600 lines of views, players and view models, and every app compiles all of it. Agreed end state: per-app UI packages, Sources/Shared gone, and the app folders holding only @main, plists and assets.

Do it after sections 1 and 2, so views aren't moved and then rewritten.

Today:

Folder Lines Goes to

Sources/Manager 9,900 ManagerUI (done 2026-11-02)
Sources/iOS 2,200 stays the phone's, or a PhoneUI
Sources/TVApp, Remote, AntennaTower under 150 stay as thin shells

Likely packages, in Packages/Station or a new Packages/StationUI:

  • StationUI: the themes' colours and views, the guide, channel screens, menus, StationModel and the other view models (TV, Mac TV and phone).
  • Players: AVKit and VLC, the only target that links VLCKit. Its 3 modules (VLCKit, TVVLCKit, MobileVLCKit) are chosen by platform.
  • ManagerUI: the Manager's windows and panes.

Decide from the code, not this list:

  1. List which app actually uses each file in Sources/Shared. A file only one app needs goes with that app. The Manager compiles Shared today, but may use little of it: 13 Manager files name StationModel.
  2. StationModel is the knot (about 1,300 lines). Everything UI reaches it, and it reaches players, audio, modules and RemoteLink. Move it with StationUI, and put players behind a protocol so StationUI doesn't link VLC. Check whether the Manager needs all of it: the assistant was the main reason, and that goes in section 4.
  3. Split Players first: it's the most isolated (11 files import AVKit, AVFoundation or VLC), and the cleanest dependency to cut.
  4. Then StationUI, then ManagerUI. One commit per move, every app building.
  5. Rename as you go, using the three kinds of channel: linear, app, multi.
  6. Move the channel screens onto ChannelModule when touched (docs/channel-modules.md); don't rewrite them for this.

Watch for:

  • The public pass. The rewriting tools have to be rebuilt first, or use the compiler loop in packages.md. Views need public far less than models: the apps only reach root views, so most of a UI package can stay internal.
  • Assets and fonts: code in a package still finds Bundle.main assets, which stay in the apps' catalogs. Bundle.module only if they move.
  • #if os(...) carries over fine; #if MANAGER and #if RELAY can't. Only ManagerMain.swift and TowerMain.swift have them, and both stay in the apps.
  • The tower's target. When the Manager's code leaves Sources/Manager, make the tower build from StationServer alone, without VLCKit.
  • just check-tvos lists modules by hand: add each new one. project.yml needs each product on each target.

Done when Sources/Shared is deleted, Sources/Manager is a shell, the tower links no UI, and all four apps build with the checks below.

5. Getting the server live #

  1. Read-ahead on Hummingbird. ReadAheadServer's listener is NWListener behind #if canImport(Network); on Linux startListener returns nil, so titles play from their address. Add a Linux route with range requests. Leave the Apple path alone at first.
  2. CI and deploy. A Forgejo job for just linux-check and the image, then the homelab GitOps repo (the deploy-app-to-homelab skill): network_mode: host, a /data volume, and the host's /var/run/dbus and /var/run/avahi-daemon/socket for avahi-publish.
  3. A test station beside the Mac mini, with its own R2 prefix and keys, until screens, invites and the mirror check out.
  4. The move: antenna-tower import <bundle> from the Mac mini (not written), the new address published, and the Mac's Manager joining as a client. See linux-server.md, stage 4.

Decided:

  • Host: luigi, plain Docker, so network_mode: host and the avahi socket work as planned.
  • On Demand downloads: a shared media directory on luigi, mounted into the tower and added as a Plex library.
  • VPN route: a Gluetun sidecar. Only provider requests go through its proxy, so the tower keeps host networking for mDNS. This needs a proxy setting the provider clients read (StreamingFetch and the Xtream client); not written.

How to work here #

just linux-check                  # needs Docker; makes rabbit-swift-linux:6.3 once
just check-tvos
swift test --package-path Packages/RetroLineup
swift test --package-path Packages/RetroRelay
xcodegen generate

Build each app without signing; the tvOS and iOS schemes need -destination generic/platform=tvOS or iOS:

xcodebuild -project RetroTV.xcodeproj -scheme RetroTV-Manager -destination platform=macOS \
  -configuration Debug -derivedDataPath .build CODE_SIGNING_ALLOWED=NO build -quiet

The Manager's tests must be signed, or the host hangs:

xcodebuild -project RetroTV.xcodeproj -scheme RetroTV-Manager -destination platform=macOS \
  -derivedDataPath .build DEVELOPMENT_TEAM=J35P7AJDN7 BUNDLE_PREFIX=tech.phin \
  -allowProvisioningUpdates test

Pitfalls met so far:

  • The tools that did the public passes (swift-syntax rewriters and scripts) were in a temporary folder and aren't in the repo. packages.md has the recipe; -diagnostic-style doesn't reach swift's emit-module step, so notes need reading from the drawn output.
  • A compiler timeout ("unable to type-check…") across modules usually hides a member that isn't public.
  • A memberwise init that's internal shows up as "missing argument for parameter 'from'": the call fell through to init(from:).
  • The default shell is zsh: $VAR holding several paths doesn't split.
  • project.yml has RetroTV-Manager as a scheme first and a target later.
  • The tower's Xcode target compiles Sources/Manager, so a new module the Manager imports must be linked there too.
