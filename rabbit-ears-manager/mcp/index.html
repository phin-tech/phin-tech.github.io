The Manager's MCP server

Rabbit Ears Manager can run an MCP server, so an assistant like Claude Code can manage the station. It can add channels, look at what's available, sort out IPTV feeds and fix sport channels, using the same code as the Manager's panes. Anything it changes shows in the Manager's window and reaches the Apple TV through iCloud, like any other change.

Decisions (2026-09-27) #

  1. It runs in the Manager, either as a local Streamable HTTP server on http://127.0.0.1:8765/mcp or as a stdio subprocess. Stdio clients launch the Manager executable with --mcp-stdio; this opens no window and uses the same tools and station settings as the app.

  2. It can change the lineup, feeds, sports and logins, but never reveals a secret. It can add, swap and remove IPTV logins (add_login, swap_login, remove_login; each checks or counts first and changes nothing until told to apply) and point feeds at other streams (remap_feeds). A password can be given to it, but no tool ever returns a password, token or stream URL with credentials in it, and nothing logs the values of its arguments.

  3. It's off until it's turned on in the Manager's Assistant pane (in the sidebar). It listens on loopback only and has no token. Any request with an Origin header gets a 403, so a web page can't reach it through DNS rebinding.

  4. test_stream plays a stream before it's trusted. It uses AVPlayer, as the Manager's own previews do, and waits up to 12 s for a picture. It reports the picture size, or why it didn't play. add_stream_url only adds what plays.

  5. Slow tools run in the background. These are the audit, the sports rescan, the full refresh, finding feeds, reloading the lineup and syncing catalogs.

    • A client with the tasks extension (io.modelcontextprotocol/tasks in the request's _meta client capabilities) gets a CreateTaskResult, then polls with tasks/get. tasks/cancel stops the job.
    • A client without it gets a job id, and polls with the job_status tool.

    Both paths share the same jobs, which are kept for an hour after they finish.

Protocol #

It supports both eras of the protocol, which the spec calls dual-era:

  • Modern (2026-07-28): the version and client capabilities come in each request's _meta. The server handles server/discover, and list results carry ttlMs and cacheScope, which Claude Code requires. An unknown version gets -32022 with the supported list.
  • Legacy (2025-03-26, 2025-06-18 and 2025-11-25): these start with initialize. The server has no sessions, since it doesn't need any.

Each request answers with JSON only, with no SSE and no GET stream. Notifications get a 202. The code is in Packages/ManagerUI/Sources/ManagerUI/Assistant/:

  • AssistantServer.swift: the Manager's listener and stdio transport.
  • AssistantTools.swift: the lineup's tools (channels, groups, streams), and the instructions sent to the model.
  • AssistantPane.swift: the pane.

The protocol and the tools that need no lineup model are in StationJobs (Packages/Station/Sources/StationJobs/MCP/), so the control room serves them too:

  • MCPProtocol.swift: HTTP and JSON-RPC, both eras.
  • MCPJobs.swift: tasks and jobs.
  • JobToolkit.swift: logins, On Demand's catalogs, sports, always-on channels and job_status.
  • MCPServer.swift, ControlRoomBackend.swift: the control room's server, on STATION_MCP_PORT (default 8765), loopback only.

The control room has the toolkit's tools only. The channel, group, number, feed and test_stream tools need the Manager's StationModel and stay in the Mac's assistant until the lineup's logic is out of it (docs/linux-server.md, stage 6).

The Go tower (tower/internal/lineup, tower/internal/tools/lineup.go) now serves the lineup tools that need only the synced settings, working the dial out from channelNumbers, channelNames, hiddenChannels, offDialChannels, addedChannels, iptvLineup and channelGroups (the rules are RetroLineup's DialNumbers, checked against the compiled Swift): list_channels, get_channel, remove_channel, restore_channel, renumber_channel, rename_channel, release_number, set_buffer, set_feeds, set_entries, set_preferred_login, merge_channels, list_groups, add_group, set_group and set_on_dial. A Plex or Pluto channel the tower can't see shows as a held number, not on the dial.

It also serves the rest of the Manager's assistant (plan steps 1c and 1d): search_channels, add_channel, add_stream_url, add_feed, find_feeds, reload_lineup, sync_catalogs, add_sport_channel, test_stream, audit, and the health tools get_errors, whats_playing, get_storage, clear_cache and get_diagnostics. Where the tower differs from the Manager:

  • Streams are checked by asking for them, not by playing them. test_stream and add_stream_url follow a playlist to its first segment (12 seconds at most) and say they could not show a picture; audit reads the start of each stream as the Manager's audit did. Provider streams go through STATION_PROXY, anything else direct.
  • Plex Live TV is not searched or tested: the tower holds no Plex account's channel list. sync_catalogs reports plex: 0. Tubi's streams can't be tested either (the audit skips them); Xumo's and Pluto's can.
  • Search looks through Xumo, Tubi, Pluto, the iptv-org US list (each kept in the cache folder, fetched again once a day) and every login's channels; names are matched by the same words and typo rules, in memory rather than in SQLite FTS.
  • get_diagnostics finds Apple TVs with Bonjour from the tower's network, so the tower must be on the Apple TV's network.
  • The channel modules' tools (MBTA, World, Video Store) are in Go. The MBTA and World channels' settings are each profile's, kept in the profile's history (pref.mbta, pref.world), so these tools take an optional profile (default main, the first). The Video Store's look is the station's synced videostore setting; its rating and year are the profile's (pref.videostoreTaste). add_world_area finds a place with OpenStreetMap's Nominatim (the Manager used Apple's search), so an area is named for its town and the full state name (Medford, Massachusetts, not Medford, MA). The MBTA's API key is MBTA_KEY (optional).

Tools #

Channels

  • list_channels, get_channel
  • search_channels: covers Plex Live TV, Xumo, Tubi, Pluto, iptv-org and every IPTV login, and hands out refs.
  • add_channel: adds a result from another login as a feed of the channel you already have, as the Live TV pane does.
  • add_stream_url, remove_channel, restore_channel, renumber_channel, rename_channel, release_number, set_buffer, test_stream

Groups (see group-channels.md)

  • list_groups, add_group, set_group
  • set_on_dial: off the dial, a channel still plays in its groups.
  • get_channel lists a group's channels, or the groups a channel is in; list_channels takes include_off_dial.

Feeds

  • set_feeds: one stream's feeds: order, take off, and which login Earlier Shows uses.
  • set_entries: an IPTV channel's streams and folders, in play order.
  • set_preferred_login: the login every stream and game on a channel tries first.
  • add_feed (to a stream, or as a new stream with as_new_stream), merge_channels
  • find_feeds: runs IPTVLinker.
  • audit

Health

  • get_errors: what the screens reported (the Errors pane), filtered by area or contains. Read-only.
  • whats_playing: what each device is playing now, from which login and for which profile, and each login's devices (Settings › Server › Devices). Read-only.
  • get_storage: each On Demand cache's size and file count (the Storage pane). Read-only.
  • clear_cache: clears one cache by id (readahead, posters, subtitles, tmdb); the title catalog can't be cleared.
  • get_diagnostics: lists the Apple TVs on the network, or with device fetches one's recent playback log (the Diagnostics pane).

Logins

  • list_logins: read-only.
  • list_vod_categories: each login's On Demand categories with title counts, which the adult filter drops (by name, or by a cached Jev tag), titles the menus drop by their own names (their names too, with show_titles), the titles in no listed category, and totals. Slow (a background job); never asks Jev.
  • search_vod: search On Demand's merged catalog (docs/vod-relay.md): titles, best first, each with its copies (login or Plex, tag, quality, file type, whether it plays as is); with_plots adds the first five titles' descriptions.
  • vod_catalog: the merged catalog on this Mac, each source's titles, size and last fetch; refresh fetches it all again (a background job).

Sports

  • list_sports, get_sport, add_sport_channel, set_sport_folder
  • override_folder, override_game: become labelled examples.
  • set_alias, set_followed_sports, set_regions
  • list_review, decide_review: Jev's queue.
  • test_game_feed
  • Always-on channels: find_always_on, add_always_on, remove_always_on, list_guide_channels, set_always_on_guide
  • rescan_sports, refresh_all

Channel modules (see channel-modules.md)

  • get_<name>, set_<name>: generated for every module from its settings. The MBTA channel's are get_mbta and set_mbta; the Video Store's are get_video_store and set_video_store (case sizes, what's shelved: see video-store.md).
  • find_mbta_stations, list_mbta_lines: the ids set_mbta takes.
  • add_world_area: a ZIP code or place as a page of the World channel.
  • The MBTA, World and Video Store tools also take an optional profile.

Other

  • sync_catalogs, reload_lineup, job_status

The Sports pane and the assistant share one EventScan, so a rescan from either shows in both.

Connecting #

claude mcp add retrotv -- "/Applications/Rabbit Ears Manager.app/Contents/MacOS/Rabbit Ears Manager" --mcp-stdio
codex mcp add retrotv -- "/Applications/Rabbit Ears Manager.app/Contents/MacOS/Rabbit Ears Manager" --mcp-stdio

The Assistant pane shows copyable stdio commands using the installed app's actual executable path. The HTTP server remains available to other clients that connect directly to http://127.0.0.1:8765/mcp. The pane also lists recent tool calls from either transport.
